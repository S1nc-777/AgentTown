## 一、三个核心问题的最终回答

### Q1: 异构协作是否真的比单 Agent 好？

**分维度答案（马里奥实验数据）：**

| 维度 | 数据 | 结论 |
|---|---|---|
| 速度 | 协作 31s vs 单 Agent 153s | ⚠️ 表面协作快，实为 fake 员工"秒提交"占位，非真实产出 |
| 成本 | 协作 ~$0.005-0.01 vs 单 Agent $0.0003 | ❌ 协作贵 15-30 倍（绝对值仍小） |
| 产出 | 协作占位文件 vs 单 Agent 19.8KB 真实游戏 | ❌ **不同质，无法定论**；当前形态协作不产真实代码 |
| 可监督性 | 81 事件全程可审计 vs 黑盒单次调用 | ✅✅ **协作独有且真实运转** |
| 流程机制 | 独立审核+确定性集成+任务编排 vs 无 | ✅✅ **协作独有且真实运转** |

**结论**：核心假设"异构多 Agent 协作优于单 Agent"在**产出维度未被证实且当前不利**；在**流程/监督维度已证实成立**。原定位（更快更好地产出）不成立，需转向。

### Q2: 目标用户是否愿意为它付成本？

无问卷数据（已取消）。基于实验的推断：个人开发者场景下（对比数据悬殊）不会有付费意愿；**团队/组织级场景**（需要流程审计、多 Agent 编排、确定性交付）才有付费理由。此假设需 P1C 后的小规模用户验证。

### Q3: 项目继续的价值主张是否成立？

**原主张**（协作产出更快更好）→ **不成立**（证据：速度优势是假象、成本劣势真实、产出无法同质对比）。
**修正主张** → **有条件成立**："**可监督的确定性多 Agent 协作流程层**"——面向需要流程纪律、审计、多 Agent 编排的团队/组织场景。成立条件：P1C 接入真实员工后，同质对照实验显示协作的流程收益能带来可衡量的产出/质量改善（哪怕速度/成本有折损）。

## 二、最终决策：A. 继续（带转向）

**定位转向**：从"异构 Agent 更快更好写代码"→"**可监督的确定性多 Agent 协作流程层**（Agent 公司的操作系统）"。

**下一步执行清单（P1C 前置）**：
1. **接真实员工**：OpenCode 员工适配器已就绪（Task 5c），公司模板改为"真实领导 + 真实员工"组合，跑马里奥同需求
2. **同质对照**：单 Agent vs 真实员工协作（同模型），对比产出质量/速度/成本——这是**最终去留判定实验**
3. **修产品缺陷**（验收发现）：CLI `core-process.ts` 硬编码 forbid 覆盖（真实用户无法 CLI 启动）；lease TTL 5s 自动暂停
4. **补机制短板**：leader 驱动循环的 pause/resume 再驱动；无输出时的诊断记录（Task 6a 审查 Minor）
5. Codex 对照（8/22 额度恢复后）与 Claude 后端稳定性排查（可选）

**去留门槛**（写进实验计划）：P1C 真实员工对照后，若协作的产出质量/流程收益仍无法抵消调度开销与成本（≥2 倍成本或 ≥2 倍耗时且无质量优势）→ 执行 B（转向为库/流程层嵌入现有工具链）或 C（停止归档）。
