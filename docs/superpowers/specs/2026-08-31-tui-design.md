# AgentTown 交互式 TUI 设计

日期：2026-08-31
状态：已获用户批准（交互模型 / 布局 / 技术栈 / 入口 / 任务向导 / 范围）

## 1. 背景与目标

当前 CLI 是单行命令模式（`agenttown status`、`agenttown pause` …）。用户希望获得 Claude Code CLI / OpenCode CLI 那样的交互式 TUI：一个常驻全屏界面，实时展示公司状态，并在底部输入框内完成操作，无需退出界面逐行敲命令。

目标：`agenttown` 无参数直接进入 TUI，成为默认体验；现有单行命令全部保留（脚本、远程场景）。

## 2. 已确认的设计决策

| 维度 | 决策 |
|---|---|
| 交互模型 | 命令 + 自然语言混合输入 |
| 主视图布局 | 状态栏 + 主区（可切换 4 视图）+ 结果区 + 输入行 |
| 技术栈 | 手写 ANSI + raw mode，零新依赖 |
| 入口 | `agenttown` 无参数直接进 TUI，成为默认体验；现有单行命令全部保留（脚本、远程场景） |
| 任务创建 | 自然语言识别出员工+任务时进入 TUI 内分步任务向导 |
| 第 1 版范围 | 4 视图切换 + 输入框执行核心命令 + 自然语言创建任务/查询 + 自动启动/重连；approve/reject/stop/cleanup 等高风险操作只展示，确认操作仍用现有命令 |

## 3. 架构

```
packages/cli/src/
  tui/
    tui.ts          # 主循环：事件驱动刷新 + 按键分发
    layout.ts       # 全屏渲染：状态栏/主区/结果区/输入行，CJK 宽度处理
    input.ts        # 输入行编辑：退格/左右移动/历史(↑↓)/中文输入兼容
    views/
      events.ts     # 事件流视图（实时滚动，带中文描述）
      tasks.ts      # 任务列表视图（按状态过滤）
      employees.ts  # 员工面板视图（角色/状态/当前任务/用量）
      approvals.ts  # 待审批列表视图
    intent.ts       # 自然语言意图识别（纯函数，可单测）
    commands.ts     # 输入框命令分发（复用现有命令的 case 逻辑）
```

约束：
- 零新增运行时依赖
- 复用现有 `client.ts`（IPC）、`render.ts`（表格渲染）、`describeEventType`
- 现有 `watch` 命令保留（非 TTY 场景下 `watch` 打印单次快照的行为不变）

## 4. 界面布局

```
┌ 状态栏 ─────────────────────────────────────────────┐
│ ● 运行中 │ 任务 3/8 │ 待审批 2 │ 员工 4 │ 视图:1事件  │
├ 主区（默认=事件流，Tab/数字键切换）───────────────────┤
│ 17:52:12  任务已提交  张三提交了"实现登录"            │
│ 17:52:14  审核已通过  李四审核通过 2 个变更           │
│ ...（实时滚动，最下行=最新事件）                       │
├ 结果区（最近一次输入的执行结果，可折叠）───────────────┤
│ ✔ 已暂停公司，checkpoint #42 已保存                  │
├ 输入行 ─────────────────────────────────────────────┤
│ > 让 leader 把登录功能做完                    [帮助?] │
└────────────────────────────────────────────────────┘
```

- 状态栏：公司状态（运行/暂停/停止/已断开）、任务数、待审批数、员工数、当前视图
- 主区：4 个视图，`Tab` 或 `1-4` 数字键切换，默认事件流
- 结果区：输入命令/指令后的执行结果回显，可折叠（避免刷屏）
- 输入行：底部常驻；`?` 查看快捷键与命令速查

## 5. 交互细节

### 5.1 快捷键

| 键 | 行为 |
|---|---|
| `Tab` / `1`-`4` | 切换主区视图（事件/任务/员工/审批） |
| `?` | 帮助面板（快捷键 + 命令速查） |
| `↑` / `↓` | 输入历史（当前会话内） |
| `←` / `→` / `Home` / `End` | 输入行光标移动 |
| `Backspace` | 删除光标前字符 |
| `Ctrl+C` | 输入非空：清空输入；输入为空：提示确认退出（两次 Ctrl+C 退出），**不自动停公司** |
| `Ctrl+L` | 清空结果区 |
| `s` | 公司未启动时：自动启动公司并刷新 |

### 5.2 输入解析（intent.ts）

匹配顺序：
1. 精确命令：`/` 前缀或已知命令名（status/tasks/pause/resume/start/watch/…）→ 直接分发
2. 任务创建模式：`让 X 做 Y` / `X 实现 Y` / `叫 X 完成 Y`（员工名 + 动词短语）→ 任务向导
3. 状态查询短语：`暂停` / `恢复` / `看下任务` / `有哪些待审批` / `员工在干嘛` → 对应动作或切视图
4. 未识别 → 结果区提示帮助与相近命令

任务向导（TUI 内分步表单）：标题 → 描述 → 负责人 → 依赖 → 确认提交。理由：多员工分配涉及依赖与验证配置，分步确认比一句话猜测可靠。

### 5.3 命令分发范围（第 1 版）

TUI 内可直接执行：`start`（含自动启动引导）、`status`、`tasks`、`timeline`、`pause`、`resume`、`workspaces`、`evidence`、`deliver`、`help`、自然语言创建的 `task submit`。主区视图切换用 `Tab`/数字键（TUI 本身即看板，无独立 `watch` 命令）。

TUI 内只展示、确认操作走现有命令：`approve`/`reject`、`stop`、`cleanup`。

## 6. 错误处理

| 场景 | 行为 |
|---|---|
| core 未启动 | 状态栏显示"公司未启动"，输入 `start` 或按 `s` 引导自动启动并刷新 |
| IPC 断连 | 状态栏 `● 已断开`，每秒自动重连，恢复后继续 |
| 输入未识别 | 结果区提示 + 相近命令列表 |
| 窗口 resize | 监听 SIGWINCH 全屏重绘 |
| Ctrl+C | 见 5.1，不自动停公司 |

## 7. 测试

- `intent.ts` 单测：20+ 条输入样例（命令/自然语言/歧义/未识别），纯函数断言
- `layout.ts` 快照测试：给定状态数据渲染固定布局（含 CJK 宽度断言）
- `commands.ts` 分发测试：输入 `pause` → 正确调用 IPC
- 手工验收：真实终端完整流程（启动 → 切视图 → 任务向导 → 暂停/恢复）

## 8. 明确不做（YAGNI）

- 不做 LLM 翻译输入（30-45s/次延迟，交互不可接受；预留 `AGENTTOWN_TUI_LLM=1` 环境变量作为未来扩展位）
- 不做多窗口/分屏/鼠标支持
- 第 1 版不做 approve/reject/stop/cleanup 的 TUI 内确认操作
- 不做自定义主题
